Process

Four steps. Zero trust required.

The entire pipeline runs in a single stateless execution. Your evidence enters, a sealed report exits, and nothing is retained.

01

Upload Evidence In-browser

Drag and drop any document — PDF, image, spreadsheet, or text. Files are processed locally in your browser and transmitted via encrypted connection for sealing. Nothing touches a database.

02

Constitutional Analysis Rules engine

The Verum Omnis Constitution — a versioned, deterministic rules engine — analyses the evidence against seven integrity rule sets covering consistency, completeness, authenticity markers, and structural integrity.

03

Dual-Hash Seal SHA-512 + SHA-256

The forensic report is sealed with two independent hash algorithms. The hash fingerprint is encoded into a QR code and submitted to OpenTimestamps for decentralised timestamp proof.

04

Verifiable Report PDF download

Download a structured forensic report containing the integrity analysis, hash seals, QR verification code, and timestamp proof. Anyone can independently verify the report's authenticity using the embedded hashes.

Cryptographic Chain of Custody

Every report carries a unique dual-hash fingerprint. Modify even a single byte and the hash changes completely — making tampering immediately detectable by anyone, anywhere, without contacting Verum Omnis.

Architecture

Five layers. One guarantee.

Each layer is independent and verifiable. The system degrades gracefully — if any layer is unavailable, the hash seal still holds.

LAYER 01

Input

Browser-based file ingestion. No server-side storage. Files exist only in volatile memory during processing.

LAYER 02

Constitution

Versioned rules engine. Seven integrity rule sets. Deterministic analysis — same input always produces the same report.

LAYER 03

Hash Engine

SHA-512 and SHA-256 computed independently. Dual-algorithm redundancy ensures integrity even if one algorithm is compromised.

LAYER 04

Timestamp

OpenTimestamps integration anchors the hash to the Bitcoin blockchain. Decentralised, third-party verifiable proof of existence.

LAYER 05

Report

Structured PDF with embedded QR code, hash fingerprints, integrity findings, and verification instructions.

Security Model

Privacy is the architecture,
not a policy.

Most platforms promise privacy through terms of service. Verum Omnis enforces it through system design.

  • No database. There is no database to breach. Documents exist in memory only during the sealing operation.
  • No user accounts. No login, no profile, no tracking. Use the service anonymously.
  • No AI training. Your documents are never used to train models. The rules engine is deterministic code, not a neural network.
  • Client-side hashing. Hash computation happens in your browser. The server receives only the hash for timestamp submission.
  • TLS encryption. All network communication uses TLS 1.3. No plaintext transmission.
  • Open source Constitution. The rules engine source is available for audit. Verify the logic yourself.
